# 投放模块 · 机械设计与装配

> 适用于智护库安无人艇（DFR1063 主控 + MG90S 舵机）。
> 电气与固件侧已经具备（`servo_release.c`，GPIO6、50 Hz），本文只讲**机械**。
> 交互演示：用浏览器打开同目录的 **`demo.html`**。

---

## 1. 方案是怎么定下来的

软件链路早就通了，缺的是能真正把救生圈放出去的机构。这个问题做了四轮，
前三次都是**几何扫描**时才发现不可行 —— 肉眼看模型完全看不出来。把过程记下来，免得重走。

| 版本 | 做法 | 怎么失败的 |
| :--- | :--- | :--- |
| v1 | 摆臂挂钩，舵机挡块压住摆臂内侧，载荷挂在臂端 | 摆臂要**向下**翻，而内侧必然在底板正上方，绕支点下翻时一定切进底板。按 10800 组参数搜索，可行解 **0**。形式问题，不是调参问题 |
| v2 | 竖直挡块压住托板尾部的配重短杆 | **复位扫掠无解**：舵机回位时要扫回原位，而托板已翻下、短杆正抬在扫掠弧内，必然被打到。挡块往下转又会扫过短杆本身 |
| v3 | 竖直销轴插在托板耳板的**通孔**里 | 销轴退出时要穿过耳板板厚区。按 3° 步长扫 0~90°，在 **21°~48°** 一直压在耳板实体上 —— 装配后卡着走，表现为"舵机动了但托板不翻" |
| **v4（采用）** | **开口缺口 + 倒扣圆盘** | 销轴沿开口直接滑出，扫描显示 **0.5°** 起就完全离开耳板；圆盘挡住竖直逃逸。两项检查全部通过 |

### 为什么必须加倒扣圆盘（这是最隐蔽的一条）

v3 就算解决了通孔问题也不成立：**一根竖直销轴插在水平板的孔里，只能挡住板在平面内的位移。**

而托板绕铰链转动时，耳板那一点的位移几乎全是**竖直**的（半径向量近水平，切向近竖直）——
于是托板可以直接沿销轴往上"滑脱"，销轴一点都挡不住。

倒扣圆盘就是为这条加的：它 Ø12 比缺口 Ø5.9 大，悬在耳板上方 0.1 mm。
托板想往上逃，耳板顶面就顶在圆盘下表面上。

### 为什么圆盘必须是独立零件

圆盘比缺口大。如果它和销轴一体打印，耳板就**装不进去**了 —— 销轴没法穿过缺口。
所以圆盘是单独一片，最后用 M2 自攻螺丝拧到销轴顶端的孔上。

```
锁定态（俯视）                        释放态（侧视）
   船内 ┌──────────────┐                  耳板随托板翻下 ╲
        │  ▣ 舵机       │                                ╲  托板倾倒 30°
        │   ○ 轴        │                     ● 铰链      ╲
   船外 │    ╭─●销轴     │                  销轴摆出 90° →
        │    │  ╰缺口    │                  缺口空出，托板自由
        └────┴───────────┘
             橙=耳板  蓝=销轴+圆盘
```

## 2. 零件清单

五个 3D 打印件 + 标准件，全部在 `stl/`：

| 文件 | 零件 | 建议材料 | 说明 |
| :--- | :--- | :--- | :--- |
| `stl/bracket.stl` | 舵机支架 | PETG / PLA+ | U 形槽 + 两侧安装耳槽 + 弹簧柱 + 4 个 M2 甲板孔 |
| `stl/horn.stl` | 摇臂 + 销轴（一体） | PETG（**不建议 PLA**，销轴受剪） | 销轴 Ø5.0、距轴 15 mm，顶端有 M2 螺孔 |
| `stl/tray_ear.stl` | 托板耳板 | PETG / PLA+ | 开口缺口 Ø5.9，开在板边 |
| `stl/cap.stl` | **倒扣圆盘**（独立件） | PETG | Ø12 × 0.85，中心 M2 孔 + 沉孔 |
| `stl/tray.stl` | 演示托板 | 任意 | 示意件，按你的船体和救生圈改 |

**标准件**

| 件 | 规格 | 数量 | 用途 |
| :--- | :--- | :--- | :--- |
| 自攻螺丝 | M2 × 8 | 4 | 支架固定到甲板 |
| 自攻螺丝 | M2 × 6 | 1 | 摇臂固定到舵机齿盘 |
| 自攻螺丝 | M2 × 6 | 1 | **倒扣圆盘固定到销轴** |
| 压簧 | 线径 0.5 mm，外径 Ø4，自由长 12 mm | 1 | 顶住摇臂尾部，保持锁定 |
| 合页 | 微型合页，或 Ø2 钢丝 + 两个轴套 | 1 | 托板铰链 |

**⚠️ 打印方向**：`horn` 竖直打印（摇臂平放、销轴朝天），销轴的层间方向与受力方向垂直，
抗剪最好。水平打印会让销轴沿层间受剪，容易断。

## 3. 装配步骤

### 3.1 舵机与支架

1. 舵机装进支架 U 形槽，**输出轴朝上**，安装耳卡进两侧水平槽。
2. 舵机轴位置：机身整体偏向 +y（轴距机身近端 3.5 mm）。
   装反了（轴朝另一端）会让销轴偏心 11 mm，缺口对不上，**投不出去**。
3. 支架用 4 颗 M2×8 固定到甲板。**先不要拧紧**，等调好行程再锁。

### 3.2 摇臂与销轴

1. 摇臂套上舵机齿盘，用 M2×6 轻轻带上（不要拧死，还要调角度）。
2. 把舵机打到 **0°**（`servo_release.c` 的 `SERVO_LOCKED_DEG`，或临时用舵机测试仪）。
3. 装上耳板和托板，**让销轴落进缺口** —— 此时摇臂的角度就是"锁定位"。
4. 拧紧摇臂螺丝。

> 这一步是整个装配的唯一关键点：**锁定位必须由销轴和缺口的实际配合来确定**，
> 不能先定死角度再去凑缺口。

### 3.3 倒扣圆盘（顺序不能错）

1. 用 M2×6 把圆盘拧到销轴顶端的 M2 孔上。
2. 拧到**圆盘底面轻触耳板顶面**即可，不要压死 —— 压死会增加摩擦，舵机要克服它。
3. 手动验证：托板往上抬应该被圆盘挡住。

**⚠️ 圆盘必须最后装。** 先装上去，耳板就套不进销轴了。

### 3.4 弹簧

1. 压簧套在支架的弹簧柱上（柱在舵机 **-x** 侧）。
2. 压缩后应顶在摇臂尾部的下表面。
3. 手动把摇臂往释放方向推，松手后应能**自己弹回**锁定位。

**这一步的意义**：断电时舵机没有保持力，靠弹簧把摇臂压在锁定位。
**没有弹簧，船一断电销轴就会被振动带着转开，载荷自己掉进水里。**

### 3.5 托板与铰链

1. 铰链轴线沿 **x** 方向，位于 y=14（`HINGE_Y`）。
2. 托板装上后前端应能自由下垂；**前端必须伸出船体外至少 30 mm**，
   否则救生圈会落在船帮上。
3. 检查托板翻到底（约 30°）时，前端不碰船体、不碰推进器。

### 3.6 机械自检（不接线）

接电之前手动做完这四步，全过再上电：

| 检查 | 期望 |
| :--- | :--- |
| 托板往前推 | 被销轴挡住，**推不动** |
| 托板往上抬 | 被倒扣圆盘挡住，**抬不动** ← *这条最容易漏* |
| 手指把摇臂往释放方向拨开 | 销轴退出缺口，托板**自己**翻下 |
| 松手 | 弹簧把摇臂推回，销轴回到原位（托板已翻下，销轴悬空） |

第四条正是 v4 相对前几版的核心优势 —— **销轴回位时不会把托板顶回去**。

## 4. 电气接线

| 信号 | 引脚 | 说明 |
| :--- | :--- | :--- |
| 舵机信号 | GPIO6 | 已在 `servo_release.c` 定义 |
| 舵机电源 | UBEC 5V/3A | **独立供电，不要用主控板载 5V** |
| 共地 | UBEC GND ↔ 主控 GND | **必须连**，否则信号无参考 |
| 去耦 | 1000 µF 并在 UBEC 5V 输出 | 吸收舵机启动冲击 |
| 下拉 | 10 kΩ，GPIO6 到 GND | 主控复位瞬间引脚高阻，防噪声抽动舵机 |

MG90S 堵转电流约 700 mA，启动瞬间更高。**不接 1000 µF 的典型症状是
"一按投放船就重启"** —— 电压跌落把 ESP32-C3 拉复位了。

## 5. 固件角度设置

| 宏 | 值 | 含义 |
| :--- | :--- | :--- |
| `SERVO_LOCKED_DEG` | 0 | 锁定位：销轴落在缺口里 |
| `SERVO_RELEASE_DEG` | 90 | 释放位：销轴摆出 |

几何扫描显示，开口缺口下销轴**离开板边即解锁**（≈1°），固件用 90° 余量极大，
不需要改。

### ⚠️ 两个必须注意的固件行为

**1. 500 ms 后自动回位**

`servo_release_tick()` 在拉出 500 ms 后把舵机写回 `SERVO_LOCKED_DEG`。
对 v4 这是**安全的**（销轴回位时托板已翻下，缺口已经不在那儿），
但如果托板因为摩擦没能在 500 ms 内翻下去，回位的销轴会重新落回缺口、
把托板挂住 —— 而且舵机不会再动第二次。

**首次实测请抬轮连点投放 10 次**，确认每次都听到托板落下的声音。
若偶发"投不出去"，把 `RELEASE_HOLD_MS` 从 500 改到 1200，或改成锁存不回位：

```c
/* servo_release.c：把 RETURNING 分支去掉，改为锁存 */
if (s_state == RELEASE_PULLING && elapsed >= RELEASE_HOLD_MS) {
    s_state = RELEASE_LATCHED;   /* 新增：停在释放位，不再回位 */
    s_release_count++;
}
```

锁存后需**手动**拨回锁定位，或断电重启（`servo_release_init()` 会重写 `SERVO_LOCKED_DEG`）。
这在比赛里反而是优点：一次投放后机构保持释放态，不会误投第二次。

**2. 上电瞬间**

`servo_release_init()` 上电就写锁定位，这是对的。但 `ledc_channel_config` 的 `duty`
初值是 0（0 µs 脉宽），对舵机等于"无信号"，上电瞬间可能抖一下。
**建议把初值改成锁定位置的占空比**：

```c
ledc_channel_config_t ch = {
    ...
    .duty = deg_to_duty(SERVO_LOCKED_DEG),   /* 原为 0 */
    .hpoint = 0,
};
```

## 6. 参数化改造

所有尺寸集中在 `drop_module.scad` 顶部。改完**一定要跑两个自检**：

```powershell
cd Hardware\Mechanical\DropModule
python verify_geometry.py      # 尺寸链：间隙、插入深度、对中
python check_pin_sweep.py      # 路径扫描：摆出是否蹭耳板 + 竖直逃逸
pwsh -File build.ps1           # 重新导出 STL 与预览
```

**`check_pin_sweep.py` 别跳过。** 通孔方案（v3）就是它查出来的 ——
肉眼看模型完全看不出"销轴会蹭着耳板走"。

| 改这个 | 会牵动 |
| :--- | :--- |
| `PIN_R`（销轴到轴距） | 释放行程、摇臂长度、缺口位置 |
| `PIN_D` / `EAR_NOTCH` | 径向间隙，单边保持 0.2~0.8 mm |
| `CAP_D` | **必须大于 `EAR_NOTCH`**，否则挡不住竖直逃逸 |
| `PIN_TOP` / `EAR_Z1` / `TRAY_Z0` | Z 向尺寸链，销轴顶必须低于托板底 |
| `SERVO_H` | 整个 Z 栈跟着上移 |

**换舵机时**（比如 MG996R）至少改 `SERVO_L`、`SERVO_W`、`SERVO_H`、`SHAFT_OFF`。
MG996R 轴在机身中部附近，`SHAFT_OFF` 要改成约 14 mm，支架和销轴位置都要跟着动。

## 7. 已知限制（如实说明）

1. **不是刚性自锁。** 销轴靠抗剪挡住托板水平位移，圆盘挡住竖直逃逸，
   弹簧保持位置。100~300 g 的载荷够用；剧烈撞击时理论上仍可能把销轴顶开。
   需要"断电绝对不掉"的话，在舵机旁再加一根**弹簧插销**
   （通电时电磁铁吸开，断电时弹簧顶出）。
2. **倒扣圆盘的螺丝是关键失效点。** 它承受载荷的竖直分力。M2 自攻进 PETG
   的拔出力约 30~50 N，本项目载荷远低于此；但**必须拧到位**，
   否则圆盘被顶飞就等于竖直方向没锁。
3. **托板是示意件。** `tray()` 只表达装配关系（70×56 mm），实际尺寸按船体改。
   改的时候保持两点：
   - 托板在 x 上占 `[TRAY_X0, TRAY_X1]`，耳板在其下方，**两者 y 向不能重叠到
     把缺口挡住**；
   - 前端伸出船体外 ≥ 30 mm。
4. **MG90S 的保持力有限。** 弹簧只能选很软的（自由长 12 mm、线径 0.5 mm），
   硬弹簧会超过堵转扭矩导致投放失败。装配后手动验证：**舵机能克服弹簧把摇臂推到位**。
5. **未做实机验证。** 自检覆盖了尺寸链、摆出路径、竖直逃逸、运动包络，
   但打印公差、摩擦、水面晃动无法在 CAD 里验证。首次下水前务必做 3.6 节的四项手动自检。

### 为什么 `build.ps1` 要先导出到 `_tmp`

OpenSCAD 用"写临时文件再原子重命名"落盘，而 `Hardware/` 目录树的权限策略
让重命名失败，报 `Can't open file ... for export`（工作区根的 `_tmp` 正常）。
脚本因此固定为"导出到 `_tmp` → 校验 → 拷入 `stl/`"。

### 为什么 `render_views.scad` 要旋转模型

OpenSCAD 2021.01 无头模式下 `--camera` 的 7 参数形式常被忽略
（实测 4 组不同相机参数渲染出 SHA256 完全相同的 PNG）。
所以改成把模型本身转到目标姿态，用默认相机看，结果确定可控。
